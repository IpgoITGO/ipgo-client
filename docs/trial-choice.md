# 체험 선택 서버 연결 (#323 / IPGO-227, Server #198)

구독 응답의 planChosenAt이 null인 첫 대시보드에서 선택을 요청한다. 체험 선택은 POST /api/billing/trial/start에 Idempotency-Key와 본문 없이 전송하고, 서버가 반환한 체험 종료일로 확인 화면을 표시한다. 실패 시 선택 창과 오류를 유지하고 같은 키로 재시도하며 요청 중 중복 선택을 막는다. 다른 기기/재로그인에서도 서버에 선택 기록이 있으면 다시 묻지 않는다. 기존 브라우저 선택 기록은 읽거나 새로 저장하지 않는다.

planChosenAt이 없는 구버전 응답은 기존 계정으로 취급하며 새 endpoint를 호출하지 않는다. Server V34 적용 전 배포 준비 중 잠깐 혼합 버전이 되는 경우를 위한 호환이다. 재가입 제한(TRIAL_ALREADY_USED)은 무료 체험 버튼을 허용하지 않고 유료 선택을 유지한다. 수불부가 있는 기존 계정은 기존 동작대로 선택 창을 띄우지 않는다.

개발 배포에서는 Server V33의 해지 사유 API·V34의 체험 선택과 함께 검증한다. 기존 DB migration workflow는 Server/AI 서비스가 모두 중지된 유지보수 구간을 요구한다. Client 코드 준비와 CI/백업을 마친 뒤 해당 구간에서 migration·Client·Server를 맞추고, Server와 AI의 기존 설정·버전/수량은 승인한 범위를 보존한다. 실제 배포와 실제 계정 성공을 로컬 모의 검사 통과로 대신하지 않는다.
