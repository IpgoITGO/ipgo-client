# MVP 통합 검증 준비

이 문서는 실행 준비다. 로컬 MSW 검사 성공과 실제 서버·AI·DB·화면 검증 성공을 구분한다.
변경된 클라이언트와 서버 코드의 리뷰·배포, 시험 계정·메일 수신자·쓰기 범위 승인을 먼저 확인한다.

## 실행 전 고정할 것

- Client/Server/AI 코드 SHA, 실제 배포 ID/TD/digest, 엔진 버전과 시험 시각을 기록한다.
- 실제 API 모드·새 브라우저 서비스워커 등록0과 HTTPS 연결을 확인한다. 기존 mock 프로필도 별도로 확인한다.
- 전용 합성 계정·창고·시험 파일 해시와 예상 변경 행/객체 범위를 고정한다. 기존 고객 계정을 재사용하지 않는다.
- 기존 업무 자료·S3 버전·큐/경보·앱 메모리의 사전 보존/안전 기준을 환경 담당의 최신 실행기로 확인한다.
- 과거 작업 창이나 과거 pass를 재사용하지 않는다. 진행 중인 관측/시험과 겹치면 새로운 안전 창을 정한다.
- 업로드 승인은 원본 DB/S3 저장뿐 아니라 CLEAN과 정제 후 자동 CALCULATE, run/result/scenario/설명 행 생성을 포함해야 한다. 계산 API를 직접 호출하지 않아도 이 쓰기는 발생한다.
- 실제 메일 수신자는 사용자 승인 대상 한 주소로 한정한다. 수신 코드·가입 토큰·비밀번호를 로그/스크린샷에 넣지 않는다.
- 정리 시 삭제가 필요하면 별도 승인받는다. 시험이 끝났다는 이유로 계정·원본·큐를 자동 삭제하지 않는다.

## 정상 흐름

1. 메일 요청→수신함 도착→코드 확인→가입→로그인을 확인한다. 메일 API 202만으로 수신 성공을 판정하지 않는다.
2. 기존 3상품 합성 9월/10월 XLSX 묶음을 재사용한다. 업로드 ID와 CLEAN DONE을 기록한다.
3. U2 또는 조건 저장 응답에서 실제 runId를 확보한다. 조건 미확정 등 runId가 없으면 완료를 표시하지 않는다.
4. 입고 조건 A를 저장한다. C2의 QUEUED/RUNNING과 화면 대기 상태, 중복 계산 잠금을 확인한다.
5. 다른 화면 이동·같은 탭 새로고침 뒤에도 동일 runId를 확인한다. DONE 뒤 대시보드·상세·시나리오의 수치가 같은 결과 ID로 바뀌는지 대조한다.
6. 조건 B로 바꾼 뒤 다른 runId와 새 계산 수치가 표시되는지 확인한다. 발주 등록·수정·취소도 각각 반환 번호/헤더로 추적한다.
7. 계산·기준일·기간·정책이 고정된 기대값과 DB/API/화면의 권장량·금액·시나리오·위험 근거를 대조한다.
8. LLM 비활성에서는 표만 보여야 한다. 이 시험은 실제 LLM 설명 생성 성공을 요구하거나 유료 LLM을 활성화하지 않는다.

기존 3상품 묶음의 예시는 2026-11-04 기준·하루 출고5·기록 재고25·B산식/배수1·입고주기7·단위1·원가100·기존 발주 없음이다.
리드타임1의 권장량15/금액1500, 리드타임7의 권장량40/금액4000은 사전 기대값이다.
날짜·정책·원본이나 서버 설정이 달라지면 기대값을 다시 산정하고, 상품 상태 분류는 당시 서버 계약과 대조한다.
실제 응답과 비교하기 전 이 수치를 실측 결과라고 기록하지 않는다.

## 실패·확인 불가 흐름

| 상황 | 확인할 결과 | 실행 범위 |
| --- | --- | --- |
| 정제 실패 | U2 FAILED와 파일 사유 표시, 계산 완료 안내 없음 | 승인한 오류 합성 파일만 사용 |
| 계산 FAILED | 실제 C2 errorMessage, 이전 정상 결과 ID/수치 유지, 재시도 방법 표시 | 운영 AI/큐를 고의 중단하지 않음. 실제 실패 생성은 별도 승인하거나 격리 환경에서 검증 |
| C2 조회 단절/시간 초과 | 계산 실패와 구분, 같은 runId GET만 재개, 업무 POST/PUT/DELETE 자동 재실행0 | 브라우저 요청 차단 또는 격리 환경 |
| 결과 갱신 조회 실패 | 계산 DONE과 화면 갱신 실패를 구분, 기존 표시 유지, 조회만 재시도 | 브라우저 읽기 요청 차단 |
| runId 없음 | 계산 시작/완료를 임의로 알리지 않음 | 실제 조건에 따라 판단 |
| 로그아웃·계정 전환 | 탭의 계산 번호와 기존 사용자 결과를 남기지 않음 | 자기 시험 세션만 종료 |

## 종료와 복구

DB/S3 기존 자료 보존과 새 합성 자료만의 변경 범위를 확인하고, 활성 job·큐/DLQ·오류·OOM/재시작과
환경 담당이 정한 회복 관측을 완료한다. 테스트 요청 수·재전송·실패 원장과 후속 성공을 구분한다.
업무 요청 결과가 불명확하면 같은 파일/저장을 재전송하지 않고 기존 ID로 상태를 확인한다.

이상이면 새 업무 요청을 멈추고 승인된 이전 Client 배포 및 Server TD로 복구한다. 복구가 추가 배포를
필요로 하면 기존에 승인된 롤백 범위를 확인한다. DB/S3를 과거 상태로 덮어쓰거나 큐를 purge하지 않는다.

실행 기록에는 관측 시각, 고정 SHA·실제 배포, 파일 해시, upload/run/result ID, C2 전이, API와 화면 대조,
보존/회복 결과와 미검증 구간을 남긴다. 사용자 인증정보와 메일 원문/코드는 기록하지 않는다.
