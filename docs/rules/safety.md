# 안전 규칙

- 공개 저장소에 token, 비밀번호, 인증서, 개인정보와 `.env` 내용을 기록하지 않습니다.
- 로컬 `.env`는 개인 작업 공간에 보관할 수 있지만 Git에 추가하거나 값·길이·일부 문자열을
  Issue, PR, Actions log와 문서에 복사하지 않습니다.
- GitHub Actions Secret은 GitHub 설정 화면에서만 등록하고 workflow에는 Secret 이름만 적습니다.
- 사용자 인증정보와 브라우저 저장 데이터가 로그나 화면에 노출되지 않게 합니다.
- 공통 UI, 인증 흐름, build 설정 변경은 영향 화면과 충돌 가능 파일을 PR에 적습니다.
- API 계약 변경은 서버 작업과의 호환성을 먼저 확인합니다.
- 삭제, 공개, 배포와 비용이 발생하는 작업은 실행 전에 대상·영향·복구 방법을 확인합니다.
- 기존 변경을 임의로 되돌리거나 현재 Issue와 무관한 파일을 commit하지 않습니다.

## 자동화 안전장치

- Jira에서 GitHub Issue를 자동 생성할 때 기준 시각과 실행당 생성 한도를 먼저 확인합니다.
- 생성 후보가 한도를 넘으면 아무 Issue도 만들지 않고 workflow를 중단합니다.
- 동기화 범위를 넓히기 전 Jira 후보 수와 기존 GitHub 연결을 읽기 방식으로 대조합니다.
- 동기화 이상 시 workflow를 비활성화하고 Jira·GitHub 양쪽 기록을 확인한 뒤 다시 활성화합니다.
- 운영 배포는 Production 후보를 smoke test한 뒤에만 승격합니다. 검증 실패 시 기존 운영 alias를
  유지합니다.
- 자동 승인·자동 병합과 스프린트 자동 배정은 안전장치로 대체하지 않으며 계속 금지합니다.
