# 해지 사유 전송 (Server #159 / IPGO-180)

내 계정의 해지 팝업은 현재 복수 선택 문구를 유지하며 `POST /api/billing/subscription/cancel`에 코드 배열을 보낸다. 아무것도 고르지 않으면 `{reasons:[]}`로 요청하고 해지를 막지 않는다.

| 화면 문구 | 전송 코드 |
|---|---|
| 가격이 부담돼요 | PRICE |
| 생각보다 잘 안 써요 | NOT_USING |
| 예측이 잘 안 맞아요 | PREDICTION_QUALITY |
| 다른 서비스를 쓸래요 | OTHER_SERVICE |
| 기타 | OTHER |

선택 코드는 정렬한 배열로 한 번 전송한다. `ipgo:cancel-reasons`를 새로 읽거나 쓰지 않으며 기존 저장값을 자동 삭제/이전하지 않는다. 실패 뒤 같은 본문 재시도는 같은 `Idempotency-Key`, 사유가 달라지면 새 키를 보낸다. 성공하면 기존처럼 구독/결제 캐시를 갱신한다. 재개·재결제·환불의 요청 본문은 유지한다.

Server159는 본문 없는 해지 및 초기 단일 `reason` 형식도 지원한다. API의 선택 note는 서버에서500자까지 받지만 이번 화면에는 메모 입력을 추가하지 않는다. 사유 전송은 실제 PG 승인/환불을 만들지 않는다.

적용 순서는 Server V33 migration 및 해지 API → Client 변경이다. 이전 서버에 Client만 배포하면 사유가 저장되지 않을 수 있으므로 서버 선행 확인이 필요하다. 현재 변경은 로컬 코드/검사 범위이며 실제 DB 적용·배포·실제 계정 해지는 별도 승인이다. 복구 시 이전 Client로 되돌릴 수 있으며 기존 서버는 본문 없는 해지를 허용한다. 이미 저장된 서버 기록은 삭제하지 않는다.
