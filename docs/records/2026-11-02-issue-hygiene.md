## 문제와 변경

기존 poll은 다른 저장소 목적지나 null이어도 과거 연결을 계속 갱신했다.
따라서 PM/서버 미러를 닫으면 Jira를 완료로 바꾸거나 미완료 Jira에서 다시 열 수 있었다.

- Jira 전용 17키, Client 제외 Issue 37건·AI 제외 1건, 참조 정본 24개를 명시했다.
- 제외는 목록 색인 전과 Issue·댓글·PR·운영 완료 쓰기 경로 모두에 적용한다.
- 참조 정본은 원본 위치만 기록하며 자동으로 상태·담당·기간·댓글을 바꾸지 않는다.
  동기화 정본은 명시적으로 `sync`를 선택한 한 Issue만 허용한다.
- PR 본문 참고 키와 commit 본문 참고 키를 상태 전환에서 제외한다.
  실제 main merge의 PR 제목은 지원하며, 완료된 Jira를 후속 PR로 재오픈하지 않는다.
- 원본 탐색도 페이지 목록을 사용하며 GitHub Search API를 호출하지 않는다.
  이관된 옛 URL을 따라 타 저장소에 쓰지 않도록 redirect를 거부한다.
- 실제 Client 인증 작업 IPGO-30/#32는 접두사가 [인증]이므로 명시적으로 Client를 유지한다.

## 실제 반영 순서·복구

현재 workflow는 기본 브랜치 dev 코드를 읽으므로 새 PR도 옛 상태 전환을 실행할 수 있다.
상태·실행 중인 run을 보관하고 승인 범위에서 동기화 workflow를 잠시 중지한다.
옛 run 종료 후 보호 코드를 반영하고 적용 SHA·설정을 확인해 재개한 뒤 이관·정리를 수행한다.
dev 병합으로 기존 Vercel 개발 배포가 실행될 수 있으나 앱 코드·main 운영 배포 변경은 없다.

실제 정리 전에 원문·댓글·담당·Jira 상태를 재조회·보관하고, 이관 뒤 실제 ID·새 번호·링크를 확인한다.
미러 종료는 `not_planned`이며 Jira 업무 완료가 아니다. 기존 담당·기간·의존성은 보존한다.
rollback 시 제외 규칙부터 없애면 미러가 재활성화될 수 있으므로 workflow부터 멈추고
원문·상태·이관 전후 식별자를 대조한다. 댓글·이슈를 삭제하는 방식으로 복구하지 않는다.
